# 灵活定位启动器

Navigator启动器不再编译项目绝对路径。AppleScript通过path to me找到自己的Resources，启动随App安装的定位器。定位器只在启动时运行，交给项目脚本后退出，不新增常驻进程、不访问网络、不扫描正文或凭证。

定位顺序：显式CODEX_NAVIGATOR_PROJECT_ROOT（如指定必须校验通过）→用户配置中的projectRoot→最多4个已登记父目录的直接子目录。每个父目录最多200个条目，不递归扫描。候选通过package名称、plugin.id、启动脚本存在及本地Git origin身份检查；只接受本项目及旧仓库名称。配置有效时即使存在其他副本也优先配置；配置失效且只有一个有效候选时重定位并原子更新配置；多个候选或无候选则明确报错，不执行猜测路径。

配置：~/.config/codex-navigator/launcher.json。定位日志：~/Library/Logs/CodexNavigator/launcher-resolution.log。启动日志：~/Library/Logs/CodexNavigator/launcher.log。配置仅含项目路径和登记父目录，没有账号正文、余额或凭证。

在登记父目录中改名或移动，可自动恢复。跨到未登记的目录，需要在新项目中运行bash scripts/install-launcher.sh。它也能明确选择多个副本中的一个。安装时保留main.previous.scpt启动脚本备份；原版App不改动。资源脚本随启动器保存，项目目录缺失时仍能输出错误日志，避免静默失败。

优点：减少改名维护；唯一候选自动恢复；多个副本不误选；日志更明确；无新增常驻内存开销。成本：多一个用户配置和短暂的启动校验；本地Git/Node运行时仍须可用；跨未登记目录需人工更新；仓库来源改变需调整允许的项目身份；每次重新安装启动器会刷新其资源副本。

定位只解决文件路径失效。宿主DOM/React接口、App版本变化、额度权限、普通启动缺少调试端口等问题仍由对应模块校验和回退，不能由灵活路径自动修复。

验证：临时仓库覆盖改名、空格/中文/特殊字符、SSH来源、符号链接去重、多个副本拒绝及外部仓库拒绝。真实启动器已安装，--resolve确认当前配置路径，无须重启当前会话。
