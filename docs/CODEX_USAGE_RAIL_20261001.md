# Codex 额度窄栏：真实接入与撤销

当前版本（2026-10-10，应用 26.1007.21159）在最窄栏常驻显示 `5h`、`周`、`重置` 三项，分别为五小时和每周剩余百分比、可用完整重置次数。数据直接来自原生菜单使用的 `rate-limit-status` 查询缓存；插件只读订阅缓存变化，不再独立请求额度接口，也不通过 CDP 定时传输额度。

初版于 2026-10-01 在应用 26.928.21956 接入，使用只读 App Server 每分钟读取额度，再经调试连接发送到界面；睡眠与断线问题见下方历史记录。现版保留本机调试会话用于安装和卸载 UI，额度更新在渲染器内部完成。不会读取对话正文、登录凭证或消耗重置次数。当前仍为非官方会话级接入，不修改应用包。

## 2026-10-07 额度刷新失效修复

真实运行日志持续出现 `Read-only quota refresh failed: Not connected`。只读额度子进程断开后，旧循环一直复用失效连接，同时界面保留上次成功数值，导致原生菜单已显示每周额度重置，窄栏仍停在旧的 16%。重新建立只读连接与应用额度工具交叉核对，均返回每周剩余 99%（检查期间已有新消耗）。

现版每次读取失败都会关闭并丢弃旧客户端，立即重连重试一次；重试仍失败则清空界面数值为 `—`，并在下一分钟继续尝试。界面超过 150 秒未收到成功更新也会清空旧值，应用重新获得焦点时补做过期检查。新增 `--attach` 更新路径可以替换现有插件而无需刷新正文。80 项测试与合成界面的数据过期、失败清空、恢复和卸载检查通过。真实窗口中主动终止插件自己的只读额度子进程后，下一次刷新自动启动了新的子进程并更新 UI；检查时数据年龄约 20 秒，且只有一个额度组件。

## 2026-10-09 睡眠唤醒后的界面连接恢复

唤醒后额度栏显示 `—`，现场刷新进程和只读额度子进程仍在运行，但日志持续出现 `Runtime.evaluate timed out`。重新连接同一窗口可以成功读取界面，证明旧的渲染器连接已失去响应；之前的修复只重建额度读取连接，未覆盖该链路。

现版在界面连接超时或关闭后丢弃旧通道，重新查询当前渲染器目标并建立连接；必要时恢复插件挂载，不刷新正文。失败时每 5 秒重试；只有应用进程退出才结束会话。重复挂载加入检查，避免重复初始化 SDK 或插件。82 项测试通过；在独立真实窗口连接中模拟无响应请求后，新通道成功恢复并读取到新额度，界面只有一个额度组件。该验证覆盖连接失效恢复，尚未再次经过完整一夜睡眠验收。

同日替换旧程序时，旧启动器因子进程被终止而弹出“插件加载失败”，但新会话实际已经正常运行。启动器现增加替代会话状态检查与短暂等待：仅当插件已挂载、更新入口存在、额度组件唯一且数据在 150 秒内更新时，认定替代会话正常；缺失或过期仍报告无法确认扩展状态。含该检查的 83 项测试通过。

## 2026-10-10 原生缓存订阅

- 已核对应用包内 `profile-dropdown-items-40c7dda3169d.js` 和 `app-shared-2f2228189a8d.js`：原生菜单使用共享额度查询；宿主支持推送，并自行保留查询与焦点刷新兜底。插件不改变这些选项、不增加 QueryObserver、不写入或使宿主缓存失效。
- 有界查找导航栏祖先的原生 QueryClient，仅筛选 `rate-limit-status` 的基础查询（默认 key 或 user/account key），只读当前有原生活动订阅的唯一查询，排除图片生成额度。无活动查询、身份不匹配、数据错误或无法验证接口时显示 `—`，不自行切回旧轮询。
- 原生事件成功更新后直接刷新三项数值；保留浮点精度直到显示时取整，避免 0% 被提前四舍五入成 1%。账户查询更换、DOM/缓存重建时清理旧订阅；退出插件时清理所有监听和观察器。
- 原生状态不套用旧外部数据的 150 秒过期时钟，数据状态由原生查询成功/错误决定；本地 focus/visibility 只重新核对缓存绑定，不发网络请求。完整一夜睡眠仍需真实复验。
- 86 项测试通过。`node scripts/e2e-native-usage.mjs` 覆盖事件更新、账户切换、错误恢复、缓存替换、零 fetch、卸载清理；Chat 90/500/1000 轮回归通过。
- 真实窗口首次检查：原生缓存与窄栏均显示 34%／90%／1 次，数据更新时间戳相同，菜单关闭；外部更新入口不存在，独立额度 App Server 子进程已退出。
- 随后在菜单关闭时观察到一次自然成功更新，窄栏与缓存不一致次数为 0；最终打开原生菜单直接对照，菜单和窄栏均显示 25%／88%／1 次。菜单验收后已关闭。旧插件轮询 controller 已移除。

## 2026-10-12 原生自动重置时间

- 当前原生缓存的五小时和每周窗口均提供 Unix 秒字段 `reset_at`。既有解析器转为 `resetsAt` 毫秒，界面直接使用该绝对时间，不根据剩余比例、读取时间或窗口长度推算。
- 每组百分比下方分别显示两行：本地日期 `M/D` 和 24 小时时刻 `HH:mm`。手动重置次数标签改为“可重置”，明确它与自动重置时间不同。屏幕阅读器可读完整年份、日期和本地时刻。
- 保持 36 px 宽和两侧留白，组件高度从 92 调整为 144 px；仍位于原生底部按钮区域上方 12 px，空间不足时沿用避让保护。
- 无时间时显示“未提供”；时间已到时显示“待更新”，不擅自把额度改为 100%。只设置一个本地到点定时器，focus/visibility 时重新核对本地显示，不增加额度网络轮询。
- 88 项测试通过；重置时间界面回归覆盖年/月/日期、时区、到点不虚构回满、缺失时间、错误清空、两种主题、文字边界、按钮间距与卸载清理。原生订阅回归另验证原生时间字段变化后立即同步。
- 当前真实窗口：五小时 `10/12 15:13`、每周 `10/18 13:39` 与原生时间戳完全对应；组件 36×144 px、底部间距 12 px、无文字溢出、无重复组件。实际时间会随原生账户状态变化，不固定为这组验收值。

## 2026-10-12 五小时改为分钟倒计时

- 五小时百分比下方只显示“剩 N 分”，不显示日期与具体时刻；N 为原生 `resetsAt` 减当前时间后向上取整的分钟数。每周仍保留本地日期 `M/D` 与时刻 `HH:mm`。
- 只在下一分钟边界设置本地定时器，不请求额度接口；原生时间变化、窗口重新获得焦点时重新计算。不到一分钟仍显示“剩1分”，时间到达显示“待更新”，不虚构额度回满。
- 组件高度缩为 132 px，沿用底部按钮自动避让与 12 px 间距。89 项测试与原生缓存、重置时间界面回归通过，覆盖分钟边界、缺失时间、周显示保持、两主题和零额外 fetch。

## 以后如何启动

1. 完全退出桌面应用（`⌘Q`）。
2. 在 Terminal 进入本仓库根目录，运行：`bash scripts/launch-usage-rail.sh`。
3. 保持这个 Terminal 进程运行。脚本校验应用签名和本机调试端口，启动实际 `/Applications/ChatGPT.app` 并加载插件。额度栏随后直接订阅宿主原生缓存。运行 `node scripts/check-session-health.mjs <本次端口>` 可检查插件状态；成功时退出码为 0。

当前会话已经由 `node scripts/inject-usage-rail.mjs` 启用，无需重复启动。若关闭 Terminal 的运行进程或按 `Ctrl+C`，插件会卸载并清除 DOM／样式；完全退出应用后普通方式打开，也回到原始状态。若要移除磁盘上的本地插件文件，可删除 `~/.explodex/plugins/codex-navigator`。停用不修改对话数据或应用签名。

额度组件本身只显示 Codex 额度，不处理普通 Chat 的搜索或滚动；同一个会话启动脚本现在还会独立启用普通 Chat 的目录与阅读锚点，详见 `docs/CHAT_SESSION_RAIL_20261001.md`。调试端口只在这次以脚本启动的应用进程上开放，使用后建议完全退出应用，再按平常方式打开。
