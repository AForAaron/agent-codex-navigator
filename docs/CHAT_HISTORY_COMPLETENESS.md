# 普通 Chat 完整目录补齐（2026-10-14）

旧目录只扫描当前已渲染 DOM。原生 Chat 使用虚拟列表，因此刻度数量会少于完整对话的提问数量。

新版在当前可见 Chat 内读取原生 entries 与选中分支 mapping，以稳定消息 ID 合并目录。只有分支父链到达根节点、且原生列表消息 ID 与该分支相符时才标记完整。无法确认时明确标记“未完整”。不会读取隐藏 Codex 会话；正文只在内存中使用，不写入目录存储。

目录点击对未渲染但原生 entries 已有的目标调用宿主 scrollToKey，再校正提问到视口顶部 82 CSS px。主动输入、会话切换和新跳转取消旧任务。原生接口失效时报告定位失败。

## 证据与限制

- 先前真实 Chat：原生选中分支 6 次提问、DOM 仅 5 次；新版目录实际显示 6 个刻度，coverage=complete。
- npm test：107 项通过。
- npm run e2e:chat：90/500/1000 轮精确定位、A→B→A、刷新恢复、清理通过。
- npm run e2e:chat:history：虚构完整历史 100 次、仅渲染 4 次，未渲染目标 0/50/96 精确跳转与清理通过。
- 新版目录按钮的真实窗口精确跳转及返回原阅读位置尚未验收；最后检查时可见窗口为 Codex。
- mapping 里的目标若尚未进入原生 entries，目前不能主动请求服务器历史页；会明确失败，不能宣称此加载路径已实现。
- 保存锚点的内容在重新打开时未渲染，现有恢复尚未接入原生加载路径；完整虚拟历史恢复仍需补齐。
- 这些是当前版本私有渲染结构适配，不是官方稳定扩展 API。应用升级可能导致能力停用。

安装产物已经包含该适配器；真实验收应通过 Codex Navigator 启动原签名应用，不卸载额度保护控制器。使用当前 Chat 做一次早期提问跳转并恢复原位置后，才能记录真实跳转通过。
