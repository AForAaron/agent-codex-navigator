# 五小时额度自动暂停与点数豁免：代码研究

日期：2026-10-12。对象：当前安装的 ChatGPT.app / Codex 26.1007.21159。

## 结论

当前版本中未找到现成的个人开关，能同时选择“五小时套餐额度用尽即暂停 / 不自动暂停 / 点数续用豁免”。原生提供额度状态、点数可用状态和线程中断能力，扩展可以设计保护策略，但不能把显示 0% 或有余额当成“当前轮实际计费来源”的证明。立即暂停只能是客户端尽力响应，不能承诺零延迟或费用硬上限。

现有 Navigator 仅显示额度、订阅状态；没有中断运行任务的 controller。本研究未启用或调用中断、消费点数、兑换重置或修改计费设置。现有自动重置时间改动保留。

## 原生字段的语义

- rate_limit.primary_window.used_percent：窗口使用比例。应按窗口时长识别五小时；不能依赖主/次窗口位置恒定。
- rate_limit.allowed / limit_reached、rate_limit_reached_type：服务端提供的可用/受限状态；可能涉及五小时、每周、模型专属限额，不是单一计费模式。
- credits.has_credits / unlimited：点数可用或无限；不是当前轮正在扣点数。
- credits.balance：余额；仅余额变化不能定位哪条线程扣费，多窗口和其他任务可以共同消耗。
- credits.overage_limit_reached、spend_control.reached：花费/超额限制；可用余额不能绕过这些限制。
- model_usage 的现场条目含 available、available_at、credits_would_enable；表示模型可用性/点数是否可使其可用，不是当前轮的实际计费来源。
- rate_limit_reset_credits.available_count：可用的额度重置次数，与付费点数余额不同。

检查的当前缓存没有可靠的逐轮 using_credits / billing_mode 等标志。该结论仅限已核查的缓存和客户端协议，不扩张为服务端永远不提供此能力。

## 停止能力与边界

官方 turn/interrupt 需要 threadId 与 turnId，成功后轮次为 interrupted。它是任务取消能力，不是额度/计费策略。必须通过拥有桌面线程的正确宿主/管理器路径，不能假定新开的独立 App Server 能取消另一个桌面实例中的任务。

原生 interruptConversation 涉及线程 owner/follower 路由与子代理清理；interruptConversationSelf 的用户停止路径还处理活跃 Goal 暂停、Node REPL 执行和后台终端。仅调用一个 turn/interrupt 不能被宣传为所有工作都永久停止或费用归零。已完成的操作不会被回滚，已发出请求的计费和在途任务存在响应延迟。

公开规则允许活动轮次在套餐限额耗尽后继续工作，受公平使用限制约束。因此“百分比到零立即停止”不是原生默认语义。

## 推荐的产品设计

1. 跟随原生（默认）：扩展不主动中断；仍受原生服务端限额和点数花费限制约束。
2. 套餐额度保护：确认当前账户、线程的套餐窗口确实达到限制后，暂停指定范围内的任务及其 Goal，阻止自动续跑。触发条件使用原始状态和时间戳，界面取整值仅用于展示。
3. 点数豁免是独立的续用授权状态：用户明确选择“允许点数继续”后，套餐保护不再中断该授权范围内的任务。原生仍拒绝续用或花费上限达到时，不能承诺继续。

需要区分两种需求：

- 若希望“原生允许点数续用就豁免”，可根据原生可用点数与受限状态做保守策略；有点数时可能从一开始就豁免，因此不是禁止自动花点数的保护。
- 若希望“套餐耗尽先暂停，只有我明确同意才使用点数”，需要独立授权按钮和作用范围，不能从 has_credits 猜测同意。

建议采用第二种明确授权的方式。状态不明、缓存过期、账户切换、第三方/API 模型计费无法确认时，只提示，不误停；点数豁免与停止策略分别显示当前状态。实施前确定只保护当前会话，还是全部本机相关会话；服务端全账号任务不能凭当前窗口承诺覆盖。

## 用户范围修订：账号保护与点数显示

用户确认保护范围为整个账号的所有对话，不限定当前线程，并接受检测延迟可能产生点数消耗。余额下降是账号级补充信号；不得据此宣称只有少量或固定上限的损失。

期望范围与可执行范围必须区分：本机宿主已发现且可管理的活跃线程，需要逐线程确认 owner、暂停目标并记录由保护触发的中断。其他设备、独立 CLI、云端任务及尚未发现的线程没有已验证的全账号暂停接口。接口缺失时必须展示覆盖不完整，不能把本机停止称为全账号停止。普通 Chat 和第三方/API 模型不能默认为同一 Codex 套餐控制对象。

恢复只接续保护功能暂停的任务；新额度快照需确认套餐窗口及相关限制解除，不能依据余额补充、倒计时归零或点数可用自动继续。恢复前按账号重新验证，跨窗口协调只能派发一次；逐个恢复并重新检查额度，避免集中启动再次耗尽。

额度栏新增“点数”，读取原生 credits.balance，保留小数；缺失显示横杠、真实零显示零。数据只在渲染器内存中使用，不保存余额、账号标识或请求凭证。仍订阅原生缓存，不新增网络轮询。显示已完成代码与本地回归，安装和真实原生余额对照须分别报告。

五小时分钟倒计时只有一个本地一次性定时器，每分钟边界最多触发一次；持有固定大小状态、复用现有 DOM 节点。相比绝对时间显示增加定时器和少量计算，不随对话长度增长，也不产生网络请求。没有隔离堆内存/CPU实测时，不给出具体 KB 或 ms 差值。


## 模式按钮 UI（2026-10-12）

已制作原生风格36×36px按钮、12.5px圆角、悬停/按下/焦点反馈及浅深主题。按钮位于点数下方，底部按钮出现时整组上移，尺寸变化由ResizeObserver重新定位。“可重置”显示文案改为“重置”。

模式选择与运行状态分离。初始原生；点击套餐保护只保存本机插件的请求偏好，明确显示“保护不可用”。偏好不是全账号控制成功、不是针对新账号的自动执行授权，也不创建恢复记录或发任何中断/接续命令。刷新后恢复选择仍须显示未接通。后续接入需要按账号确认、协调窗口并报告任务覆盖范围，不能直接复用布尔偏好执行任务控制。

本轮交付仅为按钮UI与交互，不声称自动停止/恢复完成。状态说明通过按钮title和aria-describedby提供，键盘Space/Enter使用原生button行为；关闭选择不会重启任务。正常原生状态隐藏辅助状态，尚未接通时显示“保护不可用”，不展示“保护中”。


## 链路补齐与验收（2026-10-12）

本机普通Codex任务的原生管理器中断与接续已验证：授权隔离任务第一轮120秒自然完成（不算中断证据）；第二轮600秒等待被精确中断且终态interrupted；通过原生sendFollowUpMessage提交的第三轮10秒等待正常完成。验证未修改工作任务，不伪造账号套餐耗尽。

共享状态机现按原始五小时/每周窗口判断耗尽，余额下降补充触发；120秒以上旧额度不能自动接续。只记录确认中断成功的任务ID/轮次ID，不复制正文。新账号取消旧记录，关闭/卸载取消未来接续，新轮次和手动停止作废记录。发送接续前删除记录，失败不重试，避免不确定交付重复执行。

按钮与状态机已连接，默认原生，每次重新加载须显式开启。跨窗口通过Web Locks取得本机唯一控制权。原生数据缓存仍由宿主更新；等待预计到期后通过原生Query进行一次确认，没有新增周期性网络轮询。

覆盖：当前唯一local管理器已加载的普通openai Codex任务。Goal、子代理、未加载活跃任务、第三方/API提供者、远程/云端与其他设备尚无完整接续验收，不宣称全账号保护。状态显示“本机保护”或“保护不可用”，悬停说明覆盖边界。Goal暂停原生路径已有静态证据，尚未做授权的目标生命周期测试，自动控制保持关闭。

恢复发起新轮次并要求核对已有工作，不是恢复原进程快照。已执行外部操作不回滚。暂停记录仅在当前渲染器内存中，刷新/重启后不自动续跑。自然套餐耗尽与真实补充点数的完整计费边界尚未验收，也不承诺扣点上限。

验证：95项测试；浏览器合成原始额度→原生适配器→停止→等待→新额度→接续→关闭→清理的完整模拟通过；UI、原生额度订阅、睡眠重算、隐私检查通过。模拟结果与真实原生中断/接续结果分别记录，不能把模拟额度当成真实账户耗尽验收。


## 重启修复与Goal补齐（2026-10-12，后续验收）

Navigator启动器仍引用迁移前的Codex_UI目录，导致脚本在生成日志前就失败。新增install-launcher.sh修复用户启动器引用，保留原版App签名及旧启动脚本备份。用户通过修复后的启动器重启后，日志确认本地调试会话、额度订阅及模型按钮加载。

另修复启动早期React管理器尚未挂载的问题：最多6次间隔1.5秒重试，重新获得焦点时可再尝试；晚绑定后重放最近额度证据，卸载清理重试和监听。目录仅在Chat界面挂载，不用当前Codex任务视图中的目录缺席判断插件失效。

已获额外授权执行Goal隔离验证。原生system中断将active目标改为paused并中断轮次；恢复原生Goal会自行调度后续轮次，额外发送继续消息会造成多余接续。因此普通轮次仍使用sendFollowUpMessage，Goal只使用setThreadGoalStatus(active)。单独恢复目标、不发额外消息的测试自动执行10秒等待，退出码0，目标已结束。测试过程另观察到一次模型容量不足失败，不把请求接受视为任务成功，也不自动重试失败发送。

当前已覆盖本机已加载的普通Codex任务与结构可验证的active/paused Goal。Goal修改、模型切换、账号切换或用户主动停止都会使旧恢复记录失效。子代理、未加载任务、远程/云端、其他设备仍未完成完整恢复覆盖，不能宣称全账号保护。暂停记录仍仅在当前渲染器内存中，重启后需重新开启保护。

回归更新至97项测试，浏览器模拟包含Goal先暂停后中断、Goal恢复零额外消息、模型受限时保留记录、修改Goal不误恢复。运行时仅读取最新轮次元数据，不反复展开整个对话历史；同一批元数据通知合并执行。
